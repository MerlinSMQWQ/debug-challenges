# Debug Challenges

一个以真实故障调查为核心的 Debug 挑战赛题库。训练目标是根据现场观察建立系统模型，用小实验区分假设，并解释从根因到症状的完整因果链。

每道题包含赛前知识、事故说明、可运行的调查环境，以及赛后公开的故障真相。找到可疑代码或让症状消失只是调查的一部分；完成挑战还需要可核对的证据和修复理由。

## 从哪里开始

- **第一次参加：** 阅读 [Debug 挑战赛手册](Debug%20挑战赛手册.md)第 1–4 节，了解流程、工具规则、提交内容和评分方式。
- **准备做题：** 从下表进入赛题，先读赛前文档并准备环境，再开始计时调查。每道题的具体规则以该题说明为准。
- **准备出题：** 阅读手册第 5–7 节，准备事故说明、赛前文档、事故环境和预先固定的故障真相。

**参赛前不要阅读或搜索 `organizer/`。** 该目录保存出题者的故障真相、修复与复盘材料，应在提交并结束挑战后阅读。

## 运行第一道挑战

本题需要 **macOS 和 Python 3.9+**，仅使用 Python 标准库，无需安装第三方包、容器或数据库。程序使用 POSIX 进程组与 `SIGUSR1`；Linux 尚未实测，Windows 不在支持范围。已记录的验证环境与范围见 [ENVIRONMENT.md](challenges/2026-10-09/ENVIRONMENT.md)。

克隆仓库并准备环境：

```sh
git clone https://github.com/MerlinSMQWQ/debug-challenges.git
cd debug-challenges/challenges/2026-10-09
python3 --version
python3 lab.py --help
```

先阅读本题 [README](challenges/2026-10-09/README.md) 中的赛前文档。开始调查后，在上述目录运行：

```sh
python3 lab.py reset
python3 lab.py run small --timeout 8
python3 lab.py run daily --timeout 8
```

两组输出分别保存在 `runtime/small/` 和 `runtime/daily/`。仓库提供的是含故障的事故版本，部分运行无法完成属于题目现场；超时退出码 `124` 表示运行保护停止了任务。**8 秒是运行保护时限，45 分钟是赛题时限。** 运行命令不会自动记录比赛开始时间，请按赛题规则单独记录。

需要保留现场供另一个终端观察时，可在重置后运行 `python3 lab.py run daily --timeout 0`，结束时在原终端按 `Ctrl-C`。同一组再次运行前需要重置；重置会清除本题全部 `runtime/` 输出，应先保存需要保留的证据并结束活动任务。重置保留源码修改，不会恢复原始代码。

完成修复后，按外部行为验收：

```sh
python3 lab.py reset
python3 verify.py
```

验收检查任务完成、导出记录、计数、金额和拒绝审计，两组全部通过时退出码为 `0`。通过验收是提交证据的一部分，还需解释根因与因果机制；不得修改参考输入、验收标准或保护时限来宣称修复。

## 调查与提交

调查中保留观察、假设、预测、实验、结果和判断更新，区分事实与推测。正式提交包含：

1. **ROOT CAUSE 根因：** 具体缺陷或错误条件。
2. **MECHANISM 因果机制：** 相关状态怎样变化，最终怎样产生症状。
3. **EVIDENCE 证据：** 支持结论、区分其他假设的观察和实验。
4. **TRIGGER 触发条件：** 输入、时序、配置或运行状态。
5. **FIX 修复：** 最小修复、理由与验收结果。

评分满分 100 分，重点是根因、因果机制和证据链；用时、完成状态、提示次数与 AI 模式单独记录。超时后仍可继续调查，结果标记为超时完成。

普通挑战允许查阅官方文档和工具用法，禁止搜索当前故障的现成答案，或让 AI 分析本题源码、解释异常、猜测根因和推荐调查路径。赛前可以用 AI 学习一般知识；AI 辅助挑战需要明确标记并独立记录成绩。
