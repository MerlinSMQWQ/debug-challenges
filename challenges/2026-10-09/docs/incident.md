# 事故说明：日结导出任务一直未完成

## 业务背景

运营团队每天收集门店发票，并用本地结算工具生成结算文件。调度程序启动转换程序，转换程序读取发票并产出业务结果，调度程序保存汇总和审计，供运营核对。

小批次试跑能够完成。当同一版本处理完整日结批次时，任务一直未完成，运营无法取得完整结算结果。

## 已知现象

- 样例批次 `small` 能正常结束。
- 日结批次 `daily` 在 8 秒观察窗口内没有结束，随后由运行脚本停止。
- 调度日志有启动记录，没有完成记录，也没有明确的业务失败记录。
- 在停止之前，两个业务进程仍存在，CPU 占用较低。

初始记录保存在 `evidence/initial/`，来源和文件含义见该目录的 [README](../evidence/initial/README.md)。你可以按运行指南重新建立现场。8 秒是观察和运行保护的时限，业务程序并没有在第 8 秒自动报告失败。

## 正常结果应满足什么要求

输入字段为 `invoice_id`（发票编号）、`account`（门店账户）、`currency`（币种）、`cents`（整数分金额）、`note`（备注）。`config/settlement.json` 支持 CNY、USD 和 EUR；其他币种按业务规则拒绝，拒绝一行本身不代表任务失败。

每次任务结束时应退出 `0`，并在对应运行目录保存：

| 文件 | 业务要求 |
| --- | --- |
| `exported.csv` | 按输入顺序保存所有支持币种的完整原行，不重复、不遗漏 |
| `summary.json` | 输入数、导出数、拒绝数和各支持币种的整数分金额合计 |
| `worker.log` | 每条拒绝记录对应一条 JSON 审计；包含 `event=rejected`、`reason=unsupported_currency` 和完整原行 `row` |
| `job.log` | 记录任务启动和转换进程 PID；成功时记录 `job_completed` |

两组参考输入都应在本题已验证环境的 8 秒保护时限内完成。任务完全在本地执行，不访问网络或外部服务，也没有隐藏组件。

## 你的任务

调查未完成的原因，说明触发条件以及从根因到症状的过程，保留能支持结论、区分其他假设的证据。完成修复后，通过两组业务验收，并解释为什么修复能够阻止同类故障。

修复应保持上述业务要求和完整审计。参考输入、币种配置、验收测试和保护时限是固定条件；可以用自己的副本做实验，最终验收使用仓库中的原始参考材料。
